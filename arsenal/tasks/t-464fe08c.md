Imported from issue #264

LAYOUT T8 (#208) shipped without recomputing INDEX. After round 2 of the #259 review, the disputed part was split out: LibreOffice's recompute overwrote the XE switches `\t`, `\r` and `\f`. Right now every INDEX is listed under `skipped` with an "F9 in Word" reason and left byte-identical. This leaves the plan/spec requirement "every index entry its page" (LAYOUT plan.md:88, spec.md:54) unmet.

Review notes from #263:
- **RISK:** LibreOffice rebuilds the index in its own working copy, so PAGEREF, NUMPAGES and PAGE results are computed from a layout that includes that index. The stored document keeps a one-line placeholder instead, so page numbers after the index can be off until Word refreshes the fields, and possibly after, if Word's index is a different length. Either recompute the index faithfully, keeping the XE switches, or compute page numbers with the placeholder in place.
- **NOTE:** the gate test `test_captions_xrefs_and_index_resolve_after_update` now asserts that the index keeps its placeholder; rename it. The docstring of `test_update_recomputes_each_field_type_from_a_wrong_cached_value` still says INDEX "must really be recomputed".
- **NOTE:** `fields.update` on a document whose only field is an INDEX returns early, with no `written` key in the result.
