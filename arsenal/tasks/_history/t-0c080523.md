Imported from issue #193

Asked by literary-critic (Cowork runs it in a Linux sandbox that only knows sandbox paths; the MCP server on the host needs the Windows path). Owner approved both:

1. **`live.status` without `doc`** lists the documents open in the app: full path and name of each.
2. **A bare file name as `doc`** (e.g. `Novel_v2.docx`) in `live.open`/`live.select`/`live.selection`/`live.save`/`live.close`/live `batch` resolves to the one open document with that name; none → the usual not-open error, more than one → an AMBIGUOUS-style error listing the candidates' full paths.

Both apps (Word over COM, LibreOffice over UNO). Word under OneDrive reports a URL as `FullName`: map it back to the local path (already done in `is_open`).

Acceptance: fake-adapter unit tests for both, plus a Word and a LibreOffice live scenario; the release that ships it is reported back to literary-critic.
