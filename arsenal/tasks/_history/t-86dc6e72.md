# T39: In-process Python API

Requested by literary-critic (D-19: it moves all .docx handling onto doc-control). The spec's
inter-service contract promises a "doc_control Python API (same operations as functions)".
- `doc_control.api.open(path)` returns a handle that parses the document once and re-parses
  only when the file changes; `.run(op, request)` runs any registered operation with `doc`
  filled in and returns its result dict, with no response byte cap and no paging (the caps
  exist for LLM-facing CLI/MCP only). Errors raise `DocControlError`.
- A bulk read of every paragraph: address, text, optional normalised text, style id and
  name, heading level, centred, page break before, blank before, empty, optional estimated
  page — `.paragraphs()` on the handle and the registered op `paragraphs.list` (paged on CLI/MCP).

## Acceptance gate
`api_bulk_read_mismatches == 0` — every paragraph's facts from `.paragraphs()` equal
`para.get` / `text.normalized` / `page.estimate` for the same paragraph, and the 100k-word
document is read in one call. Recorded in the plan's Evidence log (`status/plan.md`).
