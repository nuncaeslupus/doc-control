Imported from issue #255

Left open by the adversarial review of #254 (LAYOUT T4, `layout.apply`):

- **RISK:** when a plan splits a section and does not state the page-number format, the new part falls back to decimal. A lowerRoman section split this way numbers its pages i, ii, iii, 4, 5, 6. That breaks the promise that keys a plan leaves out stay as they are. The read-back check does not catch it, because it compares only the keys the plan states. **Fix:** a split part inherits the props of its source section.
- **RISK:** the real write re-reads the file instead of being pinned to the SHA it checked in the dry run. If the file changes in between and the caller passed no `expect.sha256`, the write may differ from what was checked. **Fix:** pin the write to the probed SHA.
- **NOTE:** `expect.sha256` is ignored when the plan needs no edits.
- **NOTE:** the read-back skips `from`, so where sections start is never checked.
- **NOTE:** an unknown top-level plan key returns `UNSUPPORTED_CONTENT` instead of `SCHEMA_INVALID`.
- **NOTE:** `_BREAKS` relies on `nextColumn` being the last entry in `BREAK_TYPES`.
- **NOTE:** a second apply is refused while a section still holds an unaccepted tracked change. The op's description does not say so.

Size: S.
