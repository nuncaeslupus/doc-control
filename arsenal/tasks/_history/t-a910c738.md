# Word Find strings tell a typed optional or no-break hyphen from the literal character

Follow-up of #147 / #153. Word keeps two forms of a soft hyphen and of a no-break hyphen and
matches each with a different Find code (measured in Word 16.0.17932, 64-bit):

| In the document | Saved as | Matched by | Not matched by |
|---|---|---|---|
| optional hyphen (char 31) | `<w:softHyphen/>` | `^-`, or the word typed without it | `^u173`, `^?` |
| literal U+00AD | text in `w:t` | `^u173`, `^0173`, `^?` | `^-`, the word without it |
| no-break hyphen (char 30) | `<w:noBreakHyphen/>` | `^~`, `^u30`, `^?` | `^u8209` |
| literal U+2011 | text in `w:t` | `^u8209`, `^?` | `^~` |

The text index (`src/doc_control/model/index.py`, `_FIXED_TEXT`) reads both forms as the
same character, so since #153 `word_find` gives no Find string for text holding U+00AD or
U+2011, and `locate` avoids such words when it picks a find phrase. That is safe but loses
the strings that did work for documents written with Word's own hyphens, and a paragraph
whose every word holds one gets no find phrase.

## What to do

- Keep, per paragraph, which U+00AD / U+2011 characters came from an element and which from
  `w:t` text. The index knows the source element of every piece when it builds it; every
  other builder of paragraph text (the cold bulk read, `.odt`, `.txt`/`.md`) must agree or
  say "literal".
- `locate`: write `find_phrase_word` and `context.after_word` with the code of each
  occurrence's form, and let phrases hold these words again. The uniqueness count must
  follow Word: an optional hyphen is skipped by a plain search, a literal U+00AD is not.
- `find`'s `query_word` comes from the caller's query, which has no form: keep it null for
  such a query, or document a second field. Decide and say so in the description.
- Regenerate `docs/operations.md`.

## Tests

Write failing first, in `tests/ops/test_find_hyphen_forms.py`:

- `test_hyphen_form_gate`: a document holding each of the four forms inside a word that is
  the only unique word of its paragraph; `find_phrase_word` is `ze^-bra` for the optional
  hyphen, `wal^u173rus` for the literal, and the matching pair for the no-break hyphen;
  the lazy and the whole-document indexes agree. Prints `hyphen_form_mismatches == <n>`.
- On Windows with Word, confirm once that each string finds its paragraph
  (`Range.Find.Execute`, no wildcards) and record it in the evidence row. The gate itself
  needs no Word.

## Acceptance gate

`hyphen_form_mismatches == 0`
